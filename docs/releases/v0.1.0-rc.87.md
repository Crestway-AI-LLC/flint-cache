## What you will notice

- **A seat keeps its disk guard when its volume fills** (BUG-0276). A seat
  writes its log to the same volume as its data, and a log line that could
  not be written ended the thread that wrote it. On a volume filled faster
  than the guard samples it, that was the disk guard: from then on the seat
  stopped shedding writes and reclaiming space, and `FLINTINFO` went on
  reporting the free space it last saw. Every Flint daemon now drops a log
  line it cannot write, and goes on.
- **One tenant can no longer stop the co-processor for every tenant**
  (BUG-0277). A count near 2^64 in `FT.CREATE`, `FT.SEARCH` or
  `FT.AGGREGATE`, or a huge `k` in `VEC.SEARCH`, stopped the co-processor
  from serving anyone: from then on every `VEC.` and `FT.` command, from every
  tenant, answered `-COPROCUNAVAIL` until the co-processor was restarted. The
  count is now refused as any count past the arguments is, and a `k` past
  the set returns the whole set.
- **A co-processor that fails on a command recovers by itself** (ADR-0017).
  The command is answered `-ERR the co-processor failed on this command and
  did not run it`, every other command goes on being served, and
  `FLINTINFO` counts it as `panics_total`. A failure that leaves the
  co-processor's memory in doubt ends the process instead of serving from
  it. The seat supervisor starts it again within a minute, and each
  namespace rebuilds from its durable rows, answering `-LOADING` meanwhile.
- **A `BLMPOP` or `BZMPOP` with a count near 2^64 is refused** (BUG-0278).
  The proxy closed that client's connection with no reply. It now gets the
  seat's refusal, `-ERR numkeys should be greater than 0`.

- **A seat whose background work stops ends itself** (ADR-0065). A panic
  on a seat's replication, WAL fsync, disk guard, lease or GC thread ended
  that thread alone, and the seat went on serving without it. The seat now
  exits with status 70, naming the thread, and the seat supervisor starts it
  again; a master's pair fails over as for any stopped seat. A panic on a
  thread that only reports is counted in `FLINTINFO`'s new
  `thread_panics_total`, and the seat serves on.
